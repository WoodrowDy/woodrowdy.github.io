## TL;DR

**하네스 엔지니어링(Harness Engineering)**은 AI 에이전트가 같은 실수를 반복하지 않도록 **구조적 제약**을 설계하는 접근법이다. [00:50] 프롬프트로 "잘해줘"라고 부탁하는 게 아니라, 잘못된 행동 자체가 **물리적으로 불가능한 환경**을 만드는 것. [08:38]

OpenAI 팀은 5개월간 코드 한 줄 안 쓰고 **하네스만 개선**해서 프로젝트를 완성했고 [10:39], LangChain은 모델 변경 없이 하네스만 손봐서 벤치마크 30위→5위로 올랐다. [10:47]

## 이 영상에서 영감받은 것

### 1. "말(馬)에 마구(Harness)를 씌운다"는 비유의 정확성 [01:33]
야생마는 빠르지만 방향이 무작위다. 고삐·안장·울타리 같은 **마구**가 있어야 그 힘을 **의도한 방향**으로 집중시킬 수 있다. Claude·GPT 같은 LLM도 마찬가지—모델 자체는 야생마고, `.claude.md`, pre-commit hook, MCP 같은 게 전부 하네스다. [02:13]

### 2. "컨텍스트 부패(Context Decay)" 문제의 구조적 해법 [05:20]
Anthropic이 Claude Opus로 자사 웹사이트 클론 작업을 시켰을 때:
- 컨텍스트 창이 꽉 차서 **앞 작업을 잊고** 처음부터 다시 시작 [05:41]
- 또는 "다 됐네" 하고 **조기 종료** (실제론 절반만 구현됨) [05:50]

해법: `.claude.md` 같은 **매 세션 필독 문서**. 신입사원이 바뀌어도 온보딩 문서는 항상 거기 있듯이, AI도 새 세션마다 이 파일을 먼저 읽는다. [07:03]

### 3. "규칙 위반을 원천 봉쇄"하는 자동 강제 시스템 [08:03]
프롬프트에 "DB 테이블 삭제하지 마"라고 써도 또 한다. 하지만 pre-commit hook에서 **DDL 쿼리 패턴을 린터로 차단**하면 저장 자체가 안 된다. [08:01]

이건 공장 안전 시스템과 같다: 안전모 안 쓰면 출입문이 안 열리는 것처럼, 잘못된 코드는 **시스템에서 거부**당한다. [09:13]

## 내 사이드 프로젝트에 어떻게 녹일까

### NestJS API 서버 개발 시나리오 (가정)

**문제**: Claude Code로 REST API를 작성했는데, 매번 DTO 검증 로직을 빼먹거나, `@nestjs/swagger` 데코레이터를 누락해서 Swagger 문서가 깨진다.

**하네스 적용 계획**:

1. **`.claude.md` 작성** (NestJS 컨벤션 고정)
   ```markdown
   # NestJS API 개발 규칙
   - 모든 DTO는 `class-validator` 데코레이터 필수
   - Controller 메서드에는 `@ApiOperation()`, `@ApiResponse()` 필수
   - 절대 금지: TypeORM에서 `find()` 대신 `query()` 직접 호출 (N+1 위험)
   ```

2. **Pre-commit Hook 설정** (Husky + lint-staged)
   ```json
   // package.json
   {
     "lint-staged": {
       "*.ts": [
         "eslint --fix",
         "ts-node scripts/check-dto-decorators.ts" // 커스텀 검증 스크립트
       ]
     }
   }
   ```
   → `check-dto-decorators.ts`에서 `class-validator` 데코레이터 누락 시 에러 던지기

3. **자동 교정 루프** [12:24]
   - ESLint가 에러를 뱉으면 Claude가 **자동으로 재수정** 시도
   - 사람 개입 없이 `@IsString()` 같은 데코레이터를 스스로 추가

**예상 효과**:
- DTO 검증 누락으로 인한 런타임 에러 **사전 차단**
- Swagger 문서 일관성 유지
- N+1 쿼리 패턴을 작성 단계에서 **구조적으로 방지**

## 실험 계획 (가설 → 실행 → 검증)

### 가설
"NestJS 프로젝트에 하네스(`.claude.md` + pre-commit hook)를 추가하면, Claude Code가 생성한 코드의 **재작업(Rework) 비율**이 50% 이상 줄어든다."

### 실행 단계

**Week 1: Baseline 측정**
- 하네스 없이 Claude Code로 CRUD API 5개 작성
- 측정 지표:
  - PR 코멘트 수 (사람이 수정 요청한 횟수)
  - 린터 에러 발생 건수
  - 배포 후 핫픽스 횟수

**Week 2: 하네스 구축**
- `.claude.md` 작성 (위 예시 기반)
- Husky + ESLint 규칙 강화 (`no-query-raw-sql` 같은 커스텀 룰 추가)
- DTO 데코레이터 검증 스크립트 작성

**Week 3: 재측정**
- 동일 난이도의 CRUD API 5개를 **하네스 적용 후** 작성
- 동일 지표 수집

**Week 4: 분석**
- Before/After 비교 리포트 작성
- 예상 병목: "`.claude.md`가 너무 길면 오히려 컨텍스트 낭비" [11:21] 같은 역효과 측정

### 검증 기준
- 재작업 비율 50% ↓ 달성 시: **성공**
- 20~50% ↓: 부분 성공 (규칙 추가 보완)
- 20% ↓ 미만: 실패 (하네스 설계 재검토)
